# 従業員アプリ 指示書：休暇の申請

- 対象：従業員アプリ（`Ginro540/WorkNote` の `web/`。React・TypeScript・Mantine・Firebase JS SDK）
- 出した側：管理者アプリ（`Ginro540/WorkNoteAdmin`）
- 日付：2026-10-27
- 状態：第2版（管理者が取り消したときの `cancelledBy`・`cancelReason` を追加）。下の「決まっていないこと」は推奨案で書いています。変えるときは管理者アプリ側にも知らせてください

## 1. 目的

従業員が、アプリから休暇（有給・特別休暇・欠勤）を申請できるようにします。管理者は、管理者アプリで承認または却下します。承認された休暇は、両方のアプリの勤怠の画面と集計に表示します。

今回作るのは「申請と承認」だけです。有給の残日数の管理（付与・繰り越し・年5日の取得義務）は次の段階で作ります。

## 2. 役割の分担

| | 従業員アプリ（この指示書） | 管理者アプリ（WorkNoteAdmin が作る） |
|---|---|---|
| 申請 | 作る・一覧・取り消し | — |
| 承認・却下 | — | 作る（まとめて承認、却下理由の入力） |
| 管理者による直接登録 | — | 作る（電話で連絡を受けたときなど） |
| 勤怠への表示 | 月の一覧・日の詳細・ホーム | 勤怠・出勤状況・月の集計 |
| `models.ts` の型 | 下の形をそのまま入れる | 同じものを入れる |
| セキュリティルール | **変更しない** | `WorkNoteAdmin/firebase/firestore.rules`（正本）に足して反映する |

セキュリティルールの正本は WorkNoteAdmin 側にあります。従業員アプリのリポジトリには `firestore.rules` を置かないでください。古いルールが反映されて、管理者用の許可が消えるのを防ぐためです。

**リリースの順番**：管理者アプリ側でルールを反映してから、従業員アプリを公開します。逆の順番だと、申請が permission-denied になります。

## 3. データ：`leaveRequests/{id}`

1日1件にします。複数の日をまとめて申請したときは、1日ずつのドキュメントを `writeBatch` でまとめて作り、同じ `groupId` を付けます。ID は自動の ID（`doc(collection(...))`）を使います。

| フィールド | 型 | 必須 | 内容 |
|---|---|---|---|
| `userId` | string | ○ | 申請した人の uid |
| `date` | string | ○ | 休む日 `YYYY-MM-DD`（日本時間） |
| `month` | string | ○ | 何月分か `YYYY-MM`。`settings.period.monthKeyForDayKey(date)` で求める（打刻の `month` と同じ考え方） |
| `kind` | string | ○ | 種類。下の表のどれか |
| `reason` | string | ○ | 理由。有給は空文字でよい。特別休暇・欠勤は1文字以上 |
| `groupId` | string | ○ | まとめて申請した日に共通の ID。1日だけなら、そのドキュメントの ID と同じ値 |
| `status` | string | ○ | `pending`（申請中）／`approved`（承認）／`rejected`（却下）／`cancelled`（取り消し） |
| `createdAt` | timestamp | ○ | 申請した時刻。オフラインでも申請できるよう `Timestamp.now()` を使う（修正申請と同じ） |
| `cancelledAt` | timestamp | | 本人が取り消した時刻 |
| `reviewedBy` | string | | 承認・却下した管理者の uid（管理者アプリが書く） |
| `reviewedAt` | timestamp | | 承認・却下した時刻（管理者アプリが書く） |
| `rejectReason` | string | | 却下の理由（管理者アプリが書く） |
| `createdBy` | string | | 管理者が直接登録したときだけ、その管理者の uid（管理者アプリが書く） |
| `cancelledBy` | string | | 管理者が承認済みの休暇を取り消したときの管理者の uid（管理者アプリが書く） |
| `cancelReason` | string | | 管理者が取り消したときの理由（管理者アプリが書く） |

### 種類 `kind`

| 値 | 表示 | 1日に対する日数 |
|---|---|---|
| `paid` | 有給（全日） | 1 |
| `paidAm` | 有給（午前半休） | 0.5 |
| `paidPm` | 有給（午後半休） | 0.5 |
| `special` | 特別休暇 | 1 |
| `absence` | 欠勤 | 1 |

### `models.ts` に足す型（管理者アプリと同じ）

```ts
// MARK: - 休暇（leaveRequests/{id}）

export type LeaveKind = 'paid' | 'paidAm' | 'paidPm' | 'special' | 'absence'
export type LeaveStatus = 'pending' | 'approved' | 'rejected' | 'cancelled'

export const leaveKindLabel: Record<LeaveKind, string> = {
  paid: '有給（全日）',
  paidAm: '有給（午前半休）',
  paidPm: '有給（午後半休）',
  special: '特別休暇',
  absence: '欠勤',
}

export const leaveStatusLabel: Record<LeaveStatus, string> = {
  pending: '申請中',
  approved: '承認',
  rejected: '却下',
  cancelled: '取り消し',
}

/** 1日に対する日数（集計用） */
export const leaveDays = (kind: LeaveKind) => (kind === 'paidAm' || kind === 'paidPm' ? 0.5 : 1)

/** 半休か（その日に打刻があってよい） */
export const isHalfDayLeave = (kind: LeaveKind) => kind === 'paidAm' || kind === 'paidPm'

export interface LeaveRequest {
  id: string
  userId: string
  date: string
  month: string
  kind: LeaveKind
  reason: string
  groupId: string
  status: LeaveStatus
  createdAt: Date
  cancelledAt: Date | null
  reviewedBy: string | null
  reviewedAt: Date | null
  rejectReason: string | null
  createdBy: string | null
  cancelledBy: string | null
  cancelReason: string | null
}

const leaveKinds: LeaveKind[] = ['paid', 'paidAm', 'paidPm', 'special', 'absence']
const leaveStatuses: LeaveStatus[] = ['pending', 'approved', 'rejected', 'cancelled']

export function parseLeave(id: string, d: DocumentData): LeaveRequest | null {
  if (typeof d.userId !== 'string' || typeof d.date !== 'string' || !leaveKinds.includes(d.kind)) return null
  return {
    id,
    userId: d.userId,
    date: d.date,
    month: str(d.month, d.date.slice(0, 7)),
    kind: d.kind,
    reason: str(d.reason),
    groupId: str(d.groupId, id),
    status: leaveStatuses.includes(d.status) ? d.status : 'pending',
    createdAt: toDate(d.createdAt) ?? new Date(),
    cancelledAt: toDate(d.cancelledAt),
    reviewedBy: optStr(d.reviewedBy),
    reviewedAt: toDate(d.reviewedAt),
    rejectReason: optStr(d.rejectReason),
    createdBy: optStr(d.createdBy),
    cancelledBy: optStr(d.cancelledBy),
    cancelReason: optStr(d.cancelReason),
  }
}
```

### 読み方

- 自分の分は `where('userId', '==', uid)` で購読します（修正申請と同じ）。
- 月の画面では、`month` で絞らずに `date` の範囲で選びます。締め日を変えたあとも、日付で正しく出るようにするためです。

## 4. セキュリティルール（管理者アプリ側で足す。参考）

従業員に許可するのは次の2つだけです。

- **作成**
  - 本人の分（`userId == 自分`）で、`status == 'pending'` のとき。
  - フィールドは、上の表の「管理者アプリが書く」以外に限る。
  - `kind` は5種類のどれか、`date` は `YYYY-MM-DD` の形、`reason` は string、`createdAt` は timestamp であること。
- **取り消し**
  - 本人の分で、今が `pending` のとき。
  - `status` を `cancelled` にし、`cancelledAt` を付けることだけができる。
- **削除**：できません。

管理者には、読む・承認・却下・直接登録（`status: 'approved'`、`createdBy` 付き）を許可します。

退職した人は、ほかのデータと同じく何もできません。

## 5. 画面

### 5-1. 入口

- 勤怠タブ（`PunchHomePage`）に「休暇を申請」ボタンを置きます。月の勤怠（`MonthlyAttendancePage`）の右上にも置きます。
- 申請の一覧は、修正申請の一覧（`/attendance/corrections`）と並べて `/attendance/leaves` に作ります。勤怠タブの中から行けるようにします。

### 5-2. 申請（`/attendance/leaves/new`、全画面のモーダルでもよい）

1. **種類**：5種類から選ぶ（Radio）。
2. **日付**：カレンダーで複数の日を選ぶ（`@mantine/dates` の `DatePicker type="multiple"`）。
   - `@mantine/dates` はまだ入っていないので、追加する（管理者アプリと同じ 9.7 系と `dayjs`）。
   - 日付は日本時間の `YYYY-MM-DD` として扱い、端末のタイムゾーンに左右されないようにする（`core/workCalendar.ts` の関数を使う）。
   - 土日と休業日（`settings` の休日カレンダー）は選べないようにする。欠勤だけは選べる。
   - すでに `pending` か `approved` の休暇がある日も選べないようにし、薄く「申請済み」と出す。
3. **理由**：有給は任意で、それ以外は必須。
   - 有給の欄には「有給は理由がなくても申請できます」と小さく書く（年次有給休暇は理由を求めないため）。
4. **確認**：「◯月◯日（◯）ほか◯日を ◯◯ で申請します」と出してから送る。
5. 送ったら一覧に戻り、「申請しました。管理者の承認をお待ちください」と出す。

**オフラインのとき**：修正申請と同じく、端末に保存して、つながったら送ります。一覧には「未送信」と出します。

### 5-3. 申請できる日の範囲

- **未来の日**：今日から1年後まで。
- **今日と過去の日**：その日の月の修正申請の期限まで（`settings.canRequestCorrection(month)`）。過ぎていたら「この月の申請の期限を過ぎています。管理者に連絡してください」と出して送らない。
- **全日の休暇（`paid`・`special`・`absence`）**：その日に打刻がある場合は、送る前に確かめる。「この日は出勤の打刻があります。打刻はそのまま残ります。申請しますか？」

### 5-4. 申請の一覧（`/attendance/leaves`）

- 新しい順に並べます。同じ `groupId` は1つのカードにまとめて「10/28（火）〜10/30（木） 3日」のように出します。続いていない日は「10/28, 10/31」と並べます。
- **状態のバッジ**：申請中（黄）・承認（緑）・却下（赤）・取り消し（灰）。
- **却下**：理由（`rejectReason`）を出します。
- **管理者が登録したもの**（`createdBy` がある）：「管理者が登録」と出します。
- **管理者が取り消したもの**（`cancelledBy` がある）：「管理者が取り消し」と理由（`cancelReason`）を出します。
- **取り消し**：申請中のものは、カードから取り消せます。まとめて申請したものは、全部の日か1日ずつかを選べるようにします。承認済みを取り消したいときは管理者に連絡します（画面にそう書く）。

### 5-5. 勤怠の画面への表示

- **月の勤怠（`MonthlyAttendancePage`）**
  - 承認された休暇の日は、打刻の欄に「有給」「午前半休」などを出します。申請中は「有給（申請中）」と薄く出します。
  - 月の集計に「有給 ◯日・特別休暇 ◯日・欠勤 ◯日」を足します。半休は0.5日です。承認されたものだけを数えます。
- **日の詳細（`DayDetailPage`）**：その日の休暇を、状態付きで出します。申請中なら取り消せます。
- **ホーム（`PunchHomePage`）**
  - 今日が承認された全日の休暇なら、出勤ボタンの上に「今日は有給です」と出します。打刻はできるままにします（急に出勤した場合のため）。
  - 申請中の休暇があれば「申請中の休暇 ◯件」を出し、押すと一覧を開きます。

### 5-6. 日報の「未提出」

全日の休暇（承認済み）の日は、日報の未提出に数えません。

## 6. 計算（`core/`）

実働・休憩・時間外の計算は変えません。休暇は打刻とは別に、日数として数えるだけです。半休の日に打刻があれば、今までどおり打刻から実働を計算します。

## 7. テスト

- `parseLeave`：足りないフィールドがある古いデータや、知らない `kind` が来ても落ちないこと。
- 申請できる日の判定：土日、休業日、申請済みの日、期限切れ、1年より先を正しく判定すること。
- 月の集計の日数：半休は0.5日になり、申請中・却下・取り消しは数えないこと。
- グループの表示：続いた日と、とびとびの日の書き方。

## 8. 決まっていないこと（推奨案で書いた点）

1. 種類は5種類にしました。代休・振替休日・時間単位の有給は入れていません。
2. 有給の残日数は、今回は出しません。
3. 申請できる日の範囲は、「過去は修正申請の期限まで、未来は1年先まで」にしました。
4. 承認済みの休暇は、本人からは取り消せません（管理者に連絡）。
